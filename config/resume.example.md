# Your name — master resume

Copy to `config/resume.md` and fill in. That file is gitignored; this one is the tracked
skeleton.

`tailor.py` treats this document as the only permitted source of facts. It may reorder,
reweight and rephrase what is here to match a job description. It may not add a technology, a
metric or a responsibility that is absent. So the rule is simple: **if you want a tailored
resume to be able to claim something, write it here first.**

Keep the bullets in the problem-then-action shape your real resume uses. The tailoring stage
reuses that structure, and a bullet that already names the constraint it solved is far easier to
re-angle for a different JD than one that only lists technologies.

## Notes for the tailoring stage

Things that are true and defensible but not spelled out above, so the tailoring stage is allowed
to surface them when a JD asks. This section exists because a resume compresses: you may have
real depth in something that appears as one word, or not at all.

Be precise about the boundary. "Python: built a 3,000-line pipeline, not used in production at
work" is useful, because it tells the model what it may and may not imply.
